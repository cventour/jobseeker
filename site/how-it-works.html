How it works

Plain files,
and no magic.

JobSeeker is a set of Claude Code agents, a single-file dashboard, and a folder of Markdown. There is no database, no service, and no dependencies at all.

Design principles

Fail loudly, never silently.

The dominant failure of an automation like this is quiet success — a run that reports ok having read nothing. It happened here: nine mornings in a row completed cleanly while reading no messages at all. So coverage is recorded as data rather than prose, and a sweep that extracts zero conversations is treated as a failure — a broken selector — never as an empty inbox.

Measure capability, never assume it.

Nothing is allowed to conclude "there is no browser" from context. A probe writes a machine-readable verdict and everything downstream reads that, because the inference "interactive means the browser works" turned out to be false in both directions.

Approval-gated by construction.

The unattended pipeline has no ability to submit or send. Those paths are separate, interactive, and require an approval record — not a prompt instruction that could be argued away.

The browser

Why it will not open a debugging port.

Reading WhatsApp Web needs a real, logged-in browser. The obvious route is Chrome's DevTools Protocol, and it is the wrong one: Chrome refuses a debugging port on your default profile, so getting one means launching a different profile — which means WhatsApp shows a QR code and your linked device is gone. An open port would also let any local process drive your browser as you.

So JobSeeker drives the browser you already have open, through macOS Apple Events. No restart, no port, no profile games. If Chrome is closed it is started exactly as macOS starts it at login — with no flags, because flags are what would land you on the wrong profile.

Tests

Each one guards a bug that actually happened.

  • Concurrency — parallel writers losing rows. Measured at 2 of 24 surviving before the lock existed, with no error raised anywhere.
  • Sweep — a drifted selector faking a successful read and advancing a watermark.
  • Security — path traversal through a record id, and the dashboard binding beyond loopback.
